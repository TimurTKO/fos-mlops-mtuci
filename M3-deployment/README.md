# Модуль 3. Контейнеризация, CI/CD и развёртывание ML-сервиса

## Назначение модуля

Модуль переводит обученную модель из локального Python-проекта в переносимый API-сервис и формирует воспроизводимый сценарий выпуска новой версии. Студент контейнеризирует FastAPI-приложение, описывает многокомпонентный запуск через Docker Compose, выполняет smoke-проверки и моделирует неуспешное обновление с автоматическим либо ручным откатом.

## Проверяемые индикаторы

- **LC-5.1, средний уровень** — выбор и применение практик контейнеризации, развёртывания, проверки и сопровождения ML-сервиса;
- **LC-3.1, средний уровень** — проектирование и документирование архитектуры сервиса инференса;
- **AI S -1.1, базовый уровень** — безопасная работа с конфигурациями и секретами, определение критериев отката и документирование инцидента выпуска.

## Результат модуля

К завершению модуля репозиторий должен содержать:

1. FastAPI-сервис с endpoint `/health`, `/ready` и `/predict`;
2. воспроизводимый `Dockerfile`;
3. `compose.yaml` с healthcheck и конфигурацией через переменные окружения;
4. smoke-тест, проверяющий доступность, версию и инференс;
5. две версионированные сборки сервиса: стабильную и кандидатную;
6. сценарий неуспешного выпуска и возврата к стабильной версии;
7. журнал релизов и зафиксированные критерии отката;
8. архитектурную схему и команды запуска в README.

## Последовательность выполнения

1. Завершить ЛР №6 и получить работающий контейнеризированный API.
2. Зафиксировать стабильную версию образа тегом `stable`.
3. Собрать кандидатную версию с другим номером сервиса и параметрами модели.
4. Выполнить ЛР №7: сначала смоделировать неуспешный выпуск и откат, затем провести успешное обновление.
5. На рубежной защите воспроизвести запуск, smoke-тест и один сценарий отката.

## Ограничения учебного сценария

- GPU, Kubernetes и внешний registry не требуются;
- сервис разворачивается локально через Docker Compose;
- пароли, токены и иные секреты не входят в образ и не фиксируются в Git;
- blue-green и canary рассматриваются на лекции, а в лабораторной реализуется управляемая замена версии с контролируемым откатом;
- все команды должны работать из корня базового проекта.
