# Лабораторная работа №2. Автоматизированные проверки кода, данных, модели и API

## Назначение

Сформировать набор содержательных автоматических проверок, которые подтверждают корректность компонентов учебной ML-системы.

## Проверяемые результаты и индикаторы

- **LC-5.1, средний уровень:** самостоятельно проектирует и запускает автоматизированные проверки;
- **LC-2.1, средний уровень:** использует метрики и регрессионные пороги для контроля модели.

## Исходные материалы

- проект, полученный после ЛР1;
- [`data_contract.json`](../resources/datasets/data_contract.json);
- нормальный и намеренно повреждённый варианты данных;
- минимальный API-каркас `/health` и `/predict`.

## Задание

Создать тесты `pytest`, покрывающие минимальный обязательный набор:

### Код

1. Основные функции запускаются и возвращают ожидаемые типы.
2. Некорректные аргументы приводят к ожидаемой ошибке.

### Данные

1. Присутствуют обязательные столбцы.
2. Признаки имеют числовые типы.
3. Отсутствуют недопустимые пропуски и дубликаты.
4. Целевая переменная содержит только допустимые классы.
5. Файл `incident_bad_schema.csv` не проходит проверку.

### Модель

1. Артефакт модели сохраняется и загружается.
2. Размерность предсказаний совпадает с входом.
3. Вероятности находятся в диапазоне от 0 до 1.
4. F1 на тестовой выборке не ниже согласованного порога, например 0,70.

### API

1. `/health` возвращает HTTP 200 и корректную схему.
2. `/predict` принимает валидный запрос и возвращает предсказание.
3. Неверное число признаков или неверный тип приводит к HTTP 422.

## Представляемый результат

- каталог `tests/`;
- команда единого запуска `pytest`;
- отчёт о прохождении тестов;
- таблица «проверка — риск, который она снижает»;
- демонстрация хотя бы одного намеренно падающего теста и его исправления.

## Формат защиты

Студент запускает весь набор тестов, объясняет назначение выбранных проверок и добавляет один негативный тест по устному заданию преподавателя.

## Оценивание — 5 баллов

| Критерий | Баллы |
|---|---:|
| Проверки функций и обработки ошибок | 1 |
| Контракт и качество данных | 1 |
| Проверки модели и порог метрики | 1 |
| Проверки API и кодов ошибок | 1 |
| Единый запуск, содержательность и индивидуальное объяснение | 1 |

Работа засчитывается при получении не менее 4 баллов.

## Использование генеративного ИИ

Разрешено при документировании. Автоматически созданные тесты должны быть проверены студентом: бессодержательные проверки, всегда истинные утверждения и тесты, не способные обнаружить ошибку, не учитываются.

## Использование внешних ресурсов и командная работа

- разрешены материалы курса и официальная документация используемых инструментов;
- сторонние статьи, примеры и фрагменты кода допускаются при указании источника и самостоятельной адаптации;
- запрещено выдавать чужой репозиторий или готовое решение за собственную работу;
- секреты, токены, персональные данные и закрытый код нельзя передавать внешним сервисам;
- при командной работе каждый участник фиксирует вклад в Git и проходит индивидуальную защиту;
- преподаватель вправе ограничить Интернет на отдельном этапе защиты или выдать эквивалентный локальный материал.
