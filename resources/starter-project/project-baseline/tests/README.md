# Автоматические проверки

Каталог предназначен для тестов, которые вы разрабатываете самостоятельно. Готовые тесты в студенческий комплект не входят: их проектирование и есть содержание ЛР2.

Полная постановка задания — [`kim-02-automated-checks.md`](../../../../M1-engineering-testing/kim-02-automated-checks.md).

## Обязательный минимальный состав

### Код

1. Основные функции запускаются и возвращают ожидаемые типы.
2. Некорректные аргументы приводят к ожидаемой ошибке.

### Данные

1. Присутствуют обязательные столбцы.
2. Признаки имеют числовые типы.
3. Отсутствуют недопустимые пропуски и дубликаты.
4. Целевая переменная содержит только допустимые классы.
5. Файл `data/incident_bad_schema.csv` не проходит проверку.

### Модель

1. Артефакт модели сохраняется и загружается.
2. Размерность предсказаний совпадает с входом.
3. Вероятности находятся в диапазоне от 0 до 1.
4. F1 на тестовой выборке не ниже согласованного порога.

### API

1. `/health` возвращает HTTP 200 и корректную схему.
2. `/predict` принимает валидный запрос и возвращает предсказание.
3. Неверное число признаков или неверный тип приводит к HTTP 422.

## Запуск

```bash
python scripts/generate_data.py --output-dir data
python -m mlops_course.train
pytest
```

Тесты не должны зависеть от порядка запуска, требовать сети или обращаться к платным сервисам. Тест, который проходит при заведомо некорректной реализации, не засчитывается.
