# Тест 2. Тестирование ML-систем

Назначение: короткий текущий контроль после соответствующей лекции.

Формат: 4 вопроса с выбором одного ответа. Рекомендуемое время — 5–7 минут. Максимум за тест — 1 балл.

Допустимые ресурсы: без обращения к готовому ключу; преподаватель определяет, разрешены ли конспект и официальная документация. Использование генеративного ИИ во время теста не допускается, если преподаватель прямо не установил иной режим.

## 1. Что проверяет модульный тест?

- А) Всю инфраструктуру организации
- Б) Только внешний интерфейс
- В) Отдельную функцию или компонент
- Г) Только скорость сети

## 2. Что такое контракт данных?

- А) Соглашение о схеме, типах и допустимых значениях
- Б) Лицензия на программный продукт
- В) Список пользователей API
- Г) Файл Dockerfile

## 3. Для чего нужен регрессионный тест модели?

- А) Чтобы удалить датасет
- Б) Чтобы гарантировать отсутствие значимого ухудшения относительно базовой версии
- В) Чтобы заменить Git
- Г) Чтобы построить интерфейс

## 4. Как корректно тестировать API?

- А) Только вручную смотреть браузер
- Б) Проверять только имя файла
- В) Отключать валидацию
- Г) Проверять коды ответа и схему данных

## Оценивание

- 4 правильных ответа — 1 балл;
- 3 правильных ответа — 0,75 балла;
- 2 правильных ответа — 0,5 балла;
- 0–1 правильный ответ — 0 баллов.

При переносе в LMS допускается округление в соответствии с настройками курса при сохранении общего максимума 1 балл.
