# Тест 9. Инциденты, безопасность и LLMOps

**Назначение:** короткий текущий контроль после соответствующей лекции.

**Формат:** 4 вопроса с выбором одного ответа. Рекомендуемое время — 5–7 минут. Максимум за тест — 1 балл.

**Допустимые ресурсы:** без обращения к готовому ключу; преподаватель определяет, разрешены ли конспект и официальная документация. Использование генеративного ИИ во время теста не допускается, если преподаватель прямо не установил иной режим.

## 1. Какой этап следует после обнаружения инцидента?

- А) Сбор фактов, локализация и анализ причин
- Б) Удаление всей истории Git
- В) Публикация секретов
- Г) Игнорирование события

## 2. Как снизить риск утечки API-ключа?

- А) Использовать секрет-хранилище и исключить ключ из репозитория
- Б) Записать ключ в README
- В) Добавить ключ в имя файла
- Г) Отправить ключ всем участникам

## 3. Что является допустимой мерой реагирования на неуспешное обновление?

- А) Откат к стабильной версии
- Б) Удаление всех тестов
- В) Отключение журналирования
- Г) Игнорирование ошибок

## 4. Как следует использовать генеративный ИИ в учебном проекте?

- А) Документировать использование и понимать полученный результат
- Б) Скрывать факт использования
- В) Не проверять код
- Г) Заменить защиту проекта ответом ИИ

## Оценивание

- 4 правильных ответа — 1 балл;
- 3 правильных ответа — 0,75 балла;
- 2 правильных ответа — 0,5 балла;
- 0–1 правильный ответ — 0 баллов.

При переносе в LMS допускается округление в соответствии с настройками курса при сохранении общего максимума 1 балл.
