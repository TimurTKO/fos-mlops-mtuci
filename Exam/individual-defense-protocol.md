# Протокол индивидуальной защиты

## 1. Подготовка преподавателя

До начала защиты преподаватель:

1. фиксирует URL и Git SHA/тег проекта;
2. выбирает один вопрос по основному индикатору и один по смежному;
3. выбирает одно безопасное живое изменение;
4. при командной работе просматривает историю коммитов и pull request студента;
5. не сообщает заранее точный вариант изменения.

## 2. Идентификация защищаемой версии

Студент показывает:

- URL репозитория;
- текущий Git SHA/тег;
- чистое рабочее дерево;
- состав команды и собственный вклад;
- заполненную декларацию использования ИИ.

Изменение защищаемой версии после начала процедуры допускается только с разрешения преподавателя и фиксируется в листе оценивания.

## 3. Демонстрация

Студент самостоятельно выбирает краткую последовательность команд, подтверждающую:

1. воспроизводимость данных и обучения;
2. прохождение тестов;
3. прослеживаемость выбранной модели;
4. готовность API;
5. работоспособность smoke-проверки;
6. наличие мониторинга;
7. расследование одного инцидента.

Не требуется переобучать модель длительное время, если студент показывает воспроизводимую команду и проверяемый артефакт соответствующего запуска.

## 4. Вопросы

Преподаватель задаёт не менее двух вопросов:

- один связан с основным вкладом студента;
- один проверяет понимание смежного участка жизненного цикла.

Ответ должен содержать не только определение, но и ссылку на конкретный файл, параметр, метрику или решение проекта.

## 5. Живое изменение

Студент получает небольшое изменение из банка. Требования:

1. сформулировать ожидаемый эффект и риски;
2. определить затрагиваемые файлы;
3. внести изменение;
4. добавить или обновить проверку;
5. запустить релевантный тест либо smoke-сценарий;
6. объяснить, какие ещё этапы CI/CD должны быть выполнены до выпуска.

Разрешается пользоваться официальной документацией и собственным репозиторием. Получение готового решения от другого человека или генерация полного ответа без объяснения не допускается.

## 6. Командный проект

При защите нескольких участников одного проекта преподаватель меняет вопросы и живые задания. Повторение общей демонстрации может быть сокращено, но каждый участник отдельно подтверждает:

- свой вклад;
- понимание всей архитектуры;
- способность диагностировать смежный компонент;
- выполнение индивидуального изменения.

## 7. Допустимая помощь преподавателя

Преподаватель может дать одну диагностическую подсказку, например указать на лог, тест или файл конфигурации. Подсказка учитывается при выставлении дескриптора, но не означает автоматического незачёта.

Прямое указание готового исправления означает, что соответствующий элемент индивидуальной защиты не подтверждён.

## 8. Завершение

Преподаватель:

1. фиксирует баллы по шести критериям;
2. отмечает выполнение обязательных условий;
3. записывает заданные вопросы и живое изменение;
4. формулирует замечания и, при необходимости, объём доработки;
5. сообщает студенту результат.
