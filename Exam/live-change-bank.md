# Банк небольших изменений для индивидуальной защиты

Каждое задание рассчитано примерно на 3–5 минут и выполняется только в учебном окружении. Преподаватель может адаптировать числовые значения.

| № | Изменение | Ожидаемое подтверждение |
|---:|---|---|
| 1 | Добавить отрицательный тест на отсутствие обязательного признака | тест получает ожидаемую ошибку контракта |
| 2 | Изменить допустимый диапазон одного признака | обновлены контракт и тест; объяснено влияние на совместимость |
| 3 | Добавить поле `model_version` в ответ `/predict` | схема ответа и API-тест проходят |
| 4 | Добавить новый readiness-check для наличия файла модели | `/ready` корректно меняет статус при отсутствии артефакта |
| 5 | Изменить порог F1 quality gate | параметр вынесен в конфигурацию; тестирует граничный случай |
| 6 | Добавить параметр модели в MLflow logging | новый run содержит параметр и остаётся сопоставимым |
| 7 | Добавить проверку стабильности предсказания после сериализации | тест сохраняет/загружает модель и сравнивает результат |
| 8 | Добавить smoke-проверку некорректного запроса | ожидаемый 4xx отделён от серверной ошибки |
| 9 | Изменить версию сервиса в metadata endpoint | версия видна в ответе и тесте |
| 10 | Добавить счётчик отказов валидации | метрика появляется без высококардинального label |
| 11 | Добавить предупреждение при PSI выше нового порога | отчёт и тест используют конфигурационный порог |
| 12 | Добавить в постмортем обязательное поле «владелец действия» | шаблон обновлён и объяснена проверяемость меры |
| 13 | Сделать startup failure кандидата и показать критерий отката | отказ фиксируется, стабильная версия остаётся доступной |
| 14 | Добавить один шаг в CI для проверки форматирования или lint | некорректное изменение приводит к неуспешному статусу |
| 15 | Переименовать конфигурационный параметр с сохранением обратной совместимости | миграция документирована и покрыта тестом |
| 16 | Добавить один инвариант данных: отсутствие дубликатов | негативный набор отклоняется тестом |
| 17 | Добавить таймаут в smoke-клиент | ошибка таймаута обрабатывается понятным сообщением |
| 18 | Изменить alias зарегистрированной модели и объяснить риск | загрузка по alias проверена, влияние на выпуск объяснено |

## Критерии выполнения

Живое изменение засчитывается полностью, если студент:

1. до изменения объяснил ожидаемое поведение;
2. изменил минимально необходимый набор файлов;
3. добавил или актуализировал проверку;
4. выполнил релевантную команду;
5. объяснил, почему локального теста недостаточно или достаточно для выпуска.
