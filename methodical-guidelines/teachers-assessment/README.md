# Рекомендации преподавателям по оцениванию

Оцениваются работающий артефакт, воспроизводимость, связь с индикаторами, качество документации и индивидуальное объяснение решений.

Вымышленный пример заполненного оценочного листа с пояснением выставленных баллов приведён в [assessment-example](../teachers/assessment-example.md).

## Общие принципы

- наличие файла или скриншота не заменяет демонстрацию;
- баллы выставляются по опубликованным рубрикам;
- при командной работе вклад подтверждается Git-историей и персональными вопросами;
- использование ИИ не снижает оценку само по себе, но студент обязан понимать и проверять результат;
- обязательный минимум не компенсируется рефератом без работающего артефакта.

## Модуль 4

Проверяется, способен ли студент:

1. объяснить назначение каждой метрики и избежать неконтролируемой кардинальности labels;
2. интерпретировать error rate и p95 latency;
3. различать data drift, concept drift и снижение измеренного качества;
4. сохранить доказательства и проверить не менее двух гипотез;
5. выбрать реакцию соразмерно риску;
6. доказать восстановление повторными тестами и метриками.

Красота дашборда сама по себе не является критерием. При ошибочном автоматическом переобучении без quality gate критерий реагирования не засчитывается.

## Итоговая индивидуальная защита

Защита проводится по [`Exam/individual-defense-protocol.md`](../../Exam/individual-defense-protocol.md). Для каждого студента фиксируются защищаемый Git SHA, два вопроса и одно живое изменение.

Рекомендуется:

- не оценивать презентационный стиль вместо работающего артефакта;
- задавать вопрос по основной зоне вклада и по смежному компоненту;
- выбирать изменение, которое не требует скачивания больших образов или длительного обучения;
- отличать временную техническую неисправность среды от невоспроизводимости проекта;
- снижать дескриптор при существенной диагностической помощи, но не назначать автоматический ноль за одну подсказку;
- при командной работе менять задания между участниками;
- проверять соответствие демонстрации зафиксированному Git SHA.

Баллы выставляются по шести критериям из [`Exam/README.md`](../../Exam/README.md). Если нарушено обязательное условие, в листе оценивания фиксируется причина направления на повторную защиту.
