# Рекомендации преподавателям по использованию ресурсов

Стартовый проект, датасет, шаблоны и эталонные проверки позволяют провести лабораторные работы без GPU и платных сервисов.

Сквозной порядок подготовки и проведения дисциплины приведён в [runbook](../teachers/course-runbook.md), диагностика типовых проблем окружения — в [troubleshooting](../teachers/troubleshooting.md). Результат фактического интеграционного прогона контейнерного контура и MLflow — в [integration-smoke-test](integration-smoke-test.md).

## Подготовка студенческой выдачи

1. Создать отдельную ветку или архив от базового проекта.
2. Оставить исходный ноутбук, контракт данных, генератор и постановку задачи.
3. Удалить часть готовых функций, тестов или конфигураций, заменив их `TODO`.
4. Проверить обязательный сценарий на CPU в чистом окружении.
5. Не включать эталонные ответы и полный преподавательский чек-лист в студенческую ветку.

## Модуль 2

- DVC remote может быть локальным и находиться вне Git;
- MLflow использует SQLite backend либо учебный tracking server;
- quality gate объявляется до сравнения запусков;
- студент восстанавливает хотя бы одну предыдущую версию.

## Модуль 3

- заранее проверить поддержку Docker и свободные порты;
- сохранить стабильный тег образа;
- моделировать отказ только в учебной среде;
- не помещать секреты в `.env.example` и журналы.

## Модуль 4

- заранее загрузить образы Prometheus/Grafana или предоставить VM;
- убедиться, что 8000, 9090 и 3000 свободны;
- сформировать штатную базовую линию до аномального трафика;
- распределить разные инциденты между студентами;
- для сценария `production_drift.csv` ожидать drift без обязательного падения качества;
- для `incident_degraded.csv` ожидать падение F1 при слабом одномерном PSI;
- для `incident_bad_schema.csv` ожидать остановку на проверке контракта;
- после занятия удалить локальные Docker volumes, отчёты и пароли.

## Эталонная техническая проверка

```bash
python tools/validate_repository.py
```

Полный Docker-сценарий дополнительно проверяется на машине с Docker:

```bash
docker compose --profile monitoring up -d --build
docker compose --profile validation run --rm smoke
docker compose --profile monitoring down -v
```

## Подготовка к итоговой защите

1. Подготовить локальную копию эталонного проекта и проверить обязательные команды.
2. Сформировать варианты вопросов и живых изменений из банков `Exam/`.
3. Проверить, что задания не требуют внешнего платного API и не раскрывают готовое решение целиком.
4. Для командных проектов заранее просмотреть вклад участников.
5. При защите фиксировать URL, Git SHA и результат в `Exam/assessment-sheet.md`.
6. После защиты удалить временные секреты, локальные данные и Docker volumes.
